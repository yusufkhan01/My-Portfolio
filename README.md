# Yusuf Khan — Portfolio

A static portfolio site (`index.html`) that showcases a set of small React
case studies. Each case study is a self-contained React app pre-bundled with
[esbuild](https://esbuild.github.io/) into a single `case-N.bundle.js` and
loaded from a matching `case-N.html`. No server or framework runtime is
required — the whole site is plain static files.

| Case | Page | What it is |
| ---- | ---- | ---------- |
| 1 | `case-1.html` | Distinct Detailing Ottawa — car detailing service site |
| 2 | `case-2.html` | Car Memory Match — memory card game |
| 3 | `case-3.html` | **DetailPro Garage — car care e-commerce store (SEG3125 A4)** |

---

## Getting started

Requires [Node.js](https://nodejs.org/) 18+.

```bash
# 1. Install dependencies (react, react-dom, esbuild)
npm install

# 2. Run the DetailPro Garage store in dev mode (esbuild serve + rebuild)
npm run dev
# → open the printed URL (default http://localhost:5173) — case-3.html is served

# 3. Build all case bundles for production/deployment
npm run build
# → regenerates case-1.bundle.js, case-2.bundle.js, case-3.bundle.js (minified)
```

You can also build a single case, e.g. `npm run build:case-3`.

> Tip: after `npm run build` you can preview the whole portfolio by opening
> `index.html` with any static file server (e.g. `npx serve .`). Opening the
> HTML files directly via `file://` also works.

## Project structure

```
Portfolio/
├── index.html            # portfolio landing page (links to each case)
├── styles.css            # shared styles (case-1 detail, .cm- game, .dp- store)
├── case-1.html … case-4.html
├── case-1.bundle.js …    # esbuild output (generated by npm run build)
├── package.json
└── src/
    ├── case-1.jsx        # Distinct Detailing Ottawa
    ├── case-2.jsx        # Car Memory Match
    └── case-3.jsx        # DetailPro Garage (the e-commerce store)
```

The DetailPro Garage app (`src/case-3.jsx`) is a single, clearly-sectioned
file: **data → helpers → contexts → UI atoms → layout → catalogue → pages →
app**. It uses React Context for cart state and a lightweight hash router for
navigation (see below).

## Deployment (GitHub Pages)

This repo is deployed as a GitHub Pages **project site**
(`https://<user>.github.io/My-Portfolio/`). Because everything is static, no
build step runs on GitHub — you commit the generated bundles.

1. Build the bundles locally so they are up to date:
   ```bash
   npm run build
   ```
2. Commit the generated `*.bundle.js` files together with your source:
   ```bash
   git add case-1.bundle.js case-2.bundle.js case-3.bundle.js src styles.css index.html case-3.html package.json
   git commit -m "Add DetailPro Garage e-commerce case study"
   git push
   ```
3. In the repo settings enable **Pages → Deploy from branch** (`main`, root).
   The store is then reachable from the portfolio's **DetailPro Garage** card
   or directly at `.../My-Portfolio/case-3.html`.

**Why it works on GitHub Pages:** the store navigates with a hash router
(`#/products`, `#/product/7`, `#/checkout`, …). Hash routes are handled entirely
in the browser, so deep links and the browser Back button work without any
server-side rewrites or a custom `404.html`.

## DetailPro Garage — SEG3125 Assignment 4

A high-fidelity, fully interactive car-care storefront selling detailing
products and gift cards. Everything runs client-side: the catalogue lives in
`src/case-3.jsx` and cart/checkout state is held in React state + Context
(the cart is mirrored to `localStorage`).

**Pages:** Home · Products · Product Details · Cart · Checkout · Confirmation ·
Survey · About/Contact. **Catalogue:** 31 products across all 9 categories
(car shampoo, wax, ceramic spray, tire shine, interior cleaner, microfiber
towels, detailing kits, pressure-washer accessories, gift cards).

### How each requirement is satisfied

**Faceted search (Products page)**
- Filter by category, price range (dual sliders), brand, rating, availability,
  and use case (exterior / interior / wheels / protection / gift).
- Search bar (name, brand, category, description, tags); sort by price, rating,
  and newest; live "Showing X of Y products" count; removable active-filter
  chips; and a **Clear filters** button.

**Shopping cart**
- `CartContext` provides add / update quantity / remove / clear. The navbar
  cart **badge updates live** and survives refresh via `localStorage`.
- Cart shows line totals plus **subtotal, sale savings, shipping, 13% HST, and
  total**, with a free-shipping-over-$75 progress nudge.

**Checkout flow with a visible stepper**
- Progress stepper: **Cart → Customer Info → Payment → Review → Confirmation**,
  clearly showing completed (✓), current (highlighted), and remaining steps.
- Customer form: full name, email, phone, address, city, province, postal code.
  Payment form: cardholder name, card number, expiry, CVV.
- Client-side validation (email, 10-digit phone, Canadian postal code, Luhn card
  check, non-expired MM/YY, CVV) with friendly inline messages. No real payment
  processor — placing an order shows a **fake order number** (e.g. `DPG-402913`).

**Survey**
- Rating 1–5, "what you liked", "what could be improved", a "would recommend"
  checkbox, a submit button, and a warm thank-you message after submitting.

**Three communication purposes**
- *Incite to action:* "Summer Shine Sale", "Save 15% today", "Shop best
  sellers", "Give the gift of a clean car", sale badges, free-shipping nudge.
- *Inform:* every product card and detail page states **what it does**, **who
  it's for**, and **key features**, plus price, category, rating, and stock.
- *Engage in a connection:* "We'd love your feedback" (survey) and "Thanks for
  supporting DetailPro Garage" (confirmation) use warm, friendly language.

**Writer/reader voice:** a consistent professional-but-friendly tone — a trusted
car-care expert helping everyday drivers pick the right product.

**Visual design:** dark-charcoal/black + white + electric-blue accent on
light-gray surfaces, a clean card-based layout, clear hierarchy/spacing, and a
responsive design for desktop and mobile.

**All 10 Nielsen usability heuristics**
1. *Visibility of system status* — live cart badge, "Added to cart" toasts,
   checkout stepper, free-shipping progress bar, result counts.
2. *Match between system and the real world* — real product categories, use-case
   language, Canadian provinces, 13% HST, prices in CAD.
3. *User control & freedom* — Back links everywhere, remove-item, clear cart
   (with confirm), clear filters, dismissible promo bar.
4. *Consistency & standards* — one reusable button/card/form system and shared
   design tokens.
5. *Error prevention* — required fields, formatted card/expiry inputs, disabled
   "Add to cart" when sold out, confirm before clearing the cart.
6. *Recognition rather than recall* — visible price/category/rating on cards,
   input hints/placeholders, active-filter chips, order review before paying.
7. *Flexibility & efficiency of use* — search + rich filters + sort + "Buy now".
8. *Aesthetic & minimalist design* — clean, uncluttered, card-based layout.
9. *Help users recognize, diagnose & recover from errors* — specific, friendly
   validation messages and helpful empty states.
10. *Help & documentation* — an FAQ/Help accordion on the About page.

### Tech notes
- React 18 + React DOM via `createRoot`, bundled with esbuild (`--jsx=automatic`).
- Reusable components: `ProductCard`, `ProductGrid`, `Filters`, `CartItem`,
  `CheckoutStepper`, `OrderSummary`, `StarRating`, `QtyStepper`, `Field`, `FAQ`.
- State: `CartContext` for the cart; `AppContext` for navigation, toasts, and the
  last order. No backend and no real payment processing.
